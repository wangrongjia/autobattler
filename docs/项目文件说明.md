## 🎮 核心代码文件

### 继承链（调用方向从上到下）

```
game_state.gd        ← 最底层：常量、数据、工具函数
  └─ game_flow.gd          ← 游戏流程：选将、布阵、回合、存档
      └─ combat_system.gd      ← 战斗系统：行动条、技能、伤害、羁绊
          └─ game_ui.gd            ← 界面：所有 UI 构建、渲染、交互
              └─ visual_effects.gd     ← 视觉特效：投射物、命中、飘字
                  └─ three_kingdom_game.gd  ← 启动入口：编排初始化顺序
```

> **Godot 小白说明：** 这个项目用"分层继承"组织代码。下面的脚本 `extends` 上面的脚本，逐层叠加功能。最底层 `game_state.gd` 只管数据，最顶层 `three_kingdom_game.gd` 才是实际运行入口。

### 1. `ThreeKingdom/three_kingdom_game.gd` — 启动入口（14行）

**作用：** 游戏启动时的编排脚本，决定初始化顺序。

**做的事：**
```
_ready() →
  1. 初始化随机数种子
  2. 注册 48 名扩展武将（加上 12 名招牌武将 = 60 名）
  3. 远程武将技能强度封顶
  4. 按设计文档重做 18 名武将的技能
  5. 配置蜀国核心武将的射程和速度
  6. 所有武将基础血量 ×12（相对原先 ×6 配置翻倍）
  7. 预计算技能固定数值
  8. 读取设置文件
  9. 构建游戏界面
  10. 开始新游戏
  11. 显示主菜单
```

**对应场景文件：** `ThreeKingdom.tscn`（314字节，极简——只声明根节点引用了这个脚本）

### 2. `ThreeKingdom/systems/game_state.gd` — 数据层（408行）

**作用：** 存储所有常量、武将数据、全局状态变量，以及通用查询函数。

**包含内容：**

| 类别 | 具体内容 |
|------|---------|
| **常量** | 棋盘大小(5×3)、主公血量(100000)、回合上限(15)、战斗时限(30秒)、行动条上限(100)、基础血量缩放(×12) |
| **全局状态** | 当前关卡、阶段(draft/placement/combat/finished)、双方主公血量、双方武将列表 |
| **60名武将数据** | 12名招牌武将写在 `heroes` 字典中；48名扩展武将通过 `_register_hero()` 注册 |
| **武将运行时结构** | `_make_roster_unit()` 创建一个战斗单位，包含 30+ 个字段（血量、行动条、各种状态效果） |
| **6步数据预处理** | `_rebalance_role_stats()` → `_apply_document_skill_rework()` → `_configure_combat_profiles()` → `_scale_hero_health()` → `_finalize_skill_values()` |
| **工具函数** | 找格子上的武将、检查羁绊是否激活、星级倍率计算、双语切换 |

**不包含：** UI构建逻辑、具体战斗结算、技能演出

### 3. `ThreeKingdom/systems/game_flow.gd` — 游戏流程（331行）

**作用：** 管理从"开始游戏"到"最终决战"的完整流程。

**包含内容：**

| 功能 | 函数 | 说明 |
|------|------|------|
| **新游戏** | `_new_game()` | 重置所有状态，进入第1关选将 |
| **存档/读档** | `_save_game()` / `_load_game()` | JSON格式存到 `user://three_kingdoms_save.json` |
| **选将招募** | `_generate_choices()` / `_choose_hero()` | 每关连续进行三轮三选一；每个候选位可独立刷新，锁定后不可撤销 |
| **商店刷新** | `_refresh_shop()` | 消耗刷新次数重新随机候选 |
| **升星合成** | `_try_upgrade()` | 两个同名同星武将自动合成升星 |
| **布阵** | `_on_player_cell()` / `_auto_place_player()` | 点击格子放置/移动武将，自动布阵 |
| **战斗开始** | `_start_battle()` | 收集上阵单位、应用羁绊、启动计时器 |
| **战斗结束** | `_finish_battle()` | 判定胜负、推进关卡、自动存档 |
| **最终决战** | `_start_final_battle()` | 第15关后进入无限时决战 |

**军种布阵规则（代码中的逻辑）：**
- **前军（射程1）**：只能部署在前排
- **中军（射程2）**：前排可打全场、中排打前中排、后排只打前排
- **后军（射程3）**：任意站位，随机攻击全场

### 4. `ThreeKingdom/systems/combat_system.gd` — 战斗核心（809行）

**作用：** 所有战斗逻辑——行动条推进、技能释放、伤害计算、状态效果、羁绊触发。

**核心函数：**

| 函数 | 作用 |
|------|------|
| `_battle_tick()` | 每0.2秒执行一次：推进所有武将行动条、处理持续效果、检查谁该行动 |
| `_begin_action()` | 某武将行动条满，暂停全场，开始演出 |
| `_perform_action()` | 执行具体行动：先调用 `_cast_active_skill()` |
| `_cast_active_skill()` | **技能路由器**——用 `match` 语句把每个武将路由到各自的技能函数 |
| `_cast_liubei_regen()` | 刘备的技能实现 |
| `_attack_guanyu()` | 关羽的技能实现 |
| `_cast_generic_ability()` | 通用技能引擎——30+名没有专属函数的武将都走这里 |
| `_damage()` | **核心伤害结算**——计算减伤、护盾、羁绊追击、免死、阵亡触发等 |
| `_apply_combo_bonds()` | **羁绊激活器**——检测所有人物羁绊组合，设置标记 |
| `_apply_faction_bonuses()` | 阵营羁绊——按存活人数统计四阵营并设置 2/5/8 人档位 |
| `_process_statuses()` | 每0.2秒处理所有持续效果：灼烧、眩晕、持续治疗、减速等 |

**伤害结算流程（`_damage()` 函数）：**
```
1. 检查法术抵挡（spell_ward）
2. 检查法术反弹（spell_reflect）
3. 计算易伤加成（vulnerable）
4. 计算星级倍率
5. 计算伤害增益（damage_buff + kill_buff）
6. 蜀阵营羁绊追击（expedition接力）
7. 结算蜀国动态减伤与魏国对减益目标增伤
8. 计算减伤（damage_reduction / timed_reduction / regen_magic_reduction）
9. 曹操护卫替伤（guard_link）
10. 谋略标记爆炸（strategy_mark）
11. 护盾吸收
12. 扣血 / 全能吸血
13. 检查死亡（death_prevention免死 → 阵亡触发）
14. 群阵营击杀增益 / 蜀阵营阵亡回血
```

### 5. `ThreeKingdom/systems/game_ui.gd` — 界面构建（1429行，最大文件）

**作用：** 用纯代码构建整个游戏界面，不依赖 Godot 编辑器拖拽。

**构建的界面区域：**

| 界面区域 | 函数 | 说明 |
|---------|------|------|
| **主布局** | `_build_ui()` | 1600×900 分屏布局，左右分区 |
| **棋盘** | `_board_grid()` / `_render_board()` | 双方各 5×3 网格，格子尺寸 112×82 |
| **选将弹层** | `_build_draft_layer()` | 5张候选武将卡片 |
| **武将图鉴** | `_build_encyclopedia()` / `_render_encyclopedia()` | 3列网格卡片，每卡高545px |
| **备战区** | `_render_reserve()` | 底部9格横排 |
| **战报** | `log_box` | 右侧 RichTextLabel，支持 BBCode 着色 |
| **战斗统计** | `_render_battle_stats()` | 柱状图，可切换伤害/治疗/控制/承伤 |
| **主菜单** | `_build_main_menu()` | 覆盖层，含继续/新游戏/保存/读取 |
| **设置面板** | `_build_settings_overlay()` | 速度、暂停模式、阵营过滤、武将图鉴图片显示（默认关闭） |

**图片显示逻辑：**
- `_portrait_texture()` (第824行)：加载图片时自动裁掉底部42%，只保留上面58%
- `_portrait_rect()` (第838行)：用 `STRETCH_KEEP_ASPECT_COVERED` 模式填充——类似 CSS 的 `object-fit: cover`，裁掉多余部分

**图鉴卡片结构（`_render_encyclopedia()`，第679行）：**
```
每张卡片（高545px）：
├── 立绘区域（高205px）—— 人物图片
├── 武将名 + 星级
├── 生命值 / 军种 / 读条速度
├── 技能节奏说明
└── 滚动详情区（高190px）—— 技能说明 + ★星级数值 + 羁绊
```

## 🔧 开发工具

### `tools/export_balance_snapshot.gd` — 平衡性快照导出器（1560字节）

**作用：** 在 Godot 中运行此脚本，会加载真实场景、执行全部6步数据预处理，然后导出一份 JSON 快照到 `outputs/` 目录。

**为什么不直接读源码？** 因为源码中的数值只是原始值，经过6步预处理后的实际值与源码不同。这个工具确保分析的是真实运行时数据。

```bash
godot --headless --path . --script tools/export_balance_snapshot.gd
```

### 修改武将数据
武将数据在 `game_state.gd` 中：
- **12名招牌武将**：直接写在 `var heroes := {...}` 字典中（第214行起）
- **48名扩展武将**：通过 `_add_extended_roster()` 中的 `_register_hero()` 注册（第309行起）
- **18名技能重做**：通过 `_apply_document_skill_rework()` 中的 `_set_skill()` 覆盖（第263-281行）

> **注意：** 修改原始数值后，6步预处理仍会自动执行，最终值可能与原始值不同。建议修改后运行 `export_balance_snapshot.gd` 验证。
